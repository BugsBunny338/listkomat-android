# Lístkomat for Android — agent context

Native Kotlin/Compose sibling of the iOS app: premium-SMS transit tickets for
Czech cities plus a live vehicle map. Personal/portfolio project. The product
decisions (SMS handoff, catalog-driven, confirmation-anchored validity) are in
[README.md](README.md); this file is the working context that isn't obvious
from the code.

**Start sessions from the family hub** (`~/prj/listkomat`), never from inside
this repo. The [hub CLAUDE.md](../CLAUDE.md) (`~/prj/listkomat/CLAUDE.md`) carries the cross-repo rules,
memory is keyed to the hub path, and `mobile-mcp` (`.mcp.json`) is only read
from the hub at session start.

**The iOS app is the parity spec.** Before porting a feature, read the
relevant `listkomat-ios` code end to end. Brand is shared (teal `#56C4CF`, ink,
Alte Haas Grotesk titles), but components, UX and maps stay Android-native.

## Toolchain (this Mac)

```sh
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
ADB=/opt/homebrew/share/android-commandlinetools/platform-tools/adb
```

- `local.properties` (gitignored) sets `sdk.dir=/opt/homebrew/share/android-commandlinetools`.
- `mobile-mcp` needs `ANDROID_HOME` (set in the hub `.mcp.json`) or it lists no
  devices. If it still sees none, restart MCP once, then fall back to raw
  `adb` + `uiautomator dump`.
- AVDs: `listkomat` (Pixel 7, API 35) and `api28` (Android 9, for the
  minSdk-26 code paths). Headless: `emulator -avd api28 -no-window`.
- `package cz.flipcom.listkomat`, minSdk 26, target/compile SDK 36.

## Build, test, lint

```sh
./gradlew assembleDebug test lintDebug
```

**Lint is a gate.** `NewApi` must stay at 0 errors. With minSdk 26, an
unguarded API 28/30 call compiled fine but meant that Android 8–10 never got a
location (android#16). Every brief's verification includes `lintDebug`.

Logs: `adb logcat -s Listkomat`.

## Release (Google Play)

Details and the manual console steps are in [docs/play-launch.md](docs/play-launch.md).

1. Bump `versionCode` in `app/build.gradle.kts` in its **own PR** (never inside
   a fix PR). `versionName` stays pre-1.0 until decided otherwise.
2. `./gradlew bundleRelease` **from the main checkout**. The signing files
   (`keystore.properties`, `upload-keystore.jks`, both gitignored and backed up
   in Bitwarden) exist only there. A worktree without them produces an
   unsigned bundle, so symlink both (plus `local.properties`) if you must
   build elsewhere.
3. `python3 scripts/play_release.py` `status` · `release <track>` ·
   `promote <from> <to>` · `listing <lang> [--dry-run]`. The service-account
   key lives at `~/.config/listkomat-play/service-account.json`.
4. **Release notes come from `play/release-notes/<track>.txt`, never the
   console.** Review them each release instead of carrying them over. `promote`
   uses the destination track's notes. Store texts live in `play/listing/`.
5. Images (`play/assets/icon-512.png`, `feature-1024x500.png`) are uploaded by
   hand in the console. They are generated by `listkomat-ios/Design/app-icon/render.py`,
   as is `res/drawable/ic_launcher_foreground.xml` (the feature graphic since
   listkomat-ios#38). Never hand-edit them.

Play writes and merges are Jiri's (and classifier-gated in auto mode). Closed
track "Alpha" needs ~12 opted-in testers for 14 days before production.

## Rules learned the hard way

- **No stacked PRs.** Squash-merging the base PR with `--delete-branch` closed
  the stacked one instead of retargeting it. Branch every PR off `main`.
- **PR open → code-reviewed → stop.** Paste the review summary (findings,
  what was fixed or why not) into the PR description. Jiri merges.
- **OkHttp: read response bodies inside try/catch.** An `IOException` thrown
  in `onResponse` is only logged; `onFailure` never fires, so the caller hangs.
- **Network-touching cleanup (`connectionPool.evictAll()`) runs on IO, never
  main**, because it closes sockets and throws `NetworkOnMainThreadException`
  on device.
- **Legacy `LocationListener` (the < API 30 path) must override all four
  methods.** It has no default implementations before API 30, and a missing
  override throws `AbstractMethodError` at runtime.
- The `gps` provider needs FINE location before API 31. Query
  `getProviders(true)` so you only ask providers the granted permission allows.
- SMS purchase is an `smsto:` `ACTION_SENDTO` handoff. Never `SEND_SMS` /
  `SmsManager` (Play policy + product decision). The handoff reports nothing
  back; the "did you send it?" dialog appears on return from the SMS app.
- Worktrees go in `.claude/worktrees/` (gitignored). Remove them and their
  branches after merge. Never `git stash`, because the stack is shared by
  every worktree.

## Galaxy A14 (the test phone)

Android 14 / One UI 6.0, 3-button navigation, default SMS app Google Messages.

- `am kill` does nothing while another app is on top:
  `adb shell run-as cz.flipcom.listkomat kill -9 <pid>`.
- One UI ignores the adb gesture-navigation switch, so check the gesture-bar
  contrast on the emulator.
- If a test disables the messaging apps, restore the SMS role:
  `adb shell cmd role add-role-holder android.app.role.SMS com.google.android.apps.messaging 0`.
- Keep `settings put global stay_on_while_plugged_in 7`. Re-check it and the
  adb authorization after every OTA.
- Per-app locale: `adb shell cmd locale set-app-locales cz.flipcom.listkomat --locales cs-CZ`
  (reset with `""`).
- Only one phone is connected at a time (A14 *or* the iPhone). Say which
  build you left installed.
